# 多平台店铺工作台与知识库闭环开发说明书

版本：v1.0 工作副本；2026-11-02 恢复。此前文件未出现在本轮工作目录，本副本依据本对话已经确认的完整说明书恢复要点，方便持续开发与验收；原业务要求以对话中已确认的 v1.0 为准。本文件不是已完成功能清单。

## 一、产品目标

一个桌面工具管理淘宝／天猫、抖店和拼多多的多家店铺，各店独立登录、同时接待。核心资产是店铺经营规则、商品知识、常见问答和人工修正经验。售后交人工；普通咨询自动查询、回答或补问，不能因知识缺口默认转人工，也不能编造经营事实。

闭环：接待 → 发现漏答或误判 → 人工改判／补充资料 → 原问题及边界复测 → 核对并发布知识 → 后续新会话验证 → 观察或回退。

## 二、角色与日常流程

店主负责身份、政策、权限与知识发布；客服／运营处理售后、提出修正、补资料；后台任务按授权接待、提炼候选和评测。临时处理和长期规则分开记录。

首次接入：选择平台 → 登录 → 核对身份 → 准备并核对商品和政策 → 指定会话测试 → 核对发送回显和人工接管 → 开启本店接待。日常集中处理售后、漏答、冲突及候选知识。

## 三、多平台店铺工作台

主窗口提供添加店铺、平台选择、独立登录入口、按平台筛选、启动和停止、会话及知识入口、统一人工待办与知识补全总览。切换查看店铺不停止其他后台任务，一家异常不拖停其他店。

登录、身份、消息连接、接待模式和真实验收分别显示。打开窗口不算登录成功，登录成功也不证明可收发。软件重启不默认启动接待，启动全部只覆盖已授权且具备条件的店铺。

抖店优先使用 Edge 飞鸽；拼多多使用独立商家浏览器资料；淘宝按当前条件优先适配千牛桌面客户端，不假定存在开放平台权限。千牛多账号及消息结构必须实际验证。相同远端账号不能被两个本地任务重复接待。

## 四、知识分类、共享及隔离

知识包含店铺政策、商品说明、常见问答、临时活动和接待策略。价格、库存、订单、物流按授权业务来源查询或使用有明确有效期的缓存，不把旧聊天当作实时数据。

每条知识记录范围、内容、条件、例外、来源、有效期、负责人、审核、版本、替代关系及回归问题。草稿、待核对、待复测、已生效和停用分开；冲突可见，过期退出使用，发布及回退留痕。

同商家可共用已确认的材质、尺寸等属性；各平台店铺的价格、库存、活动和政策分别维护。顾客昵称相同不合并身份。商家、平台、店铺、会话范围用于全部查询、发布、发送和统计；不同商家不串知识。

## 五、接待处理

接收及去重 → 核对角色和会话 → 结合双方历史、结构化条件和摘要理解意图 → 查询事实 → 回答、补问或售后转人工 → 检查依据和权限 → 发送前重核 → 回显确认 → 记录结果和缺口。

支持多问题、口语、简称、纠正、商品切换和日期判断。例如“啥时候到”区分售前送达、物流和退款到账；“寄广东，不是湖南”要更新地区。缺顾客条件只补问必要条件，缺店铺资料生成后台任务并说明具体不能确认的部分。

## 六、人工改判

会话中可以纠正意图、商品／规格／订单归属、事实答案和后续动作，记录原因及操作者。改判立即使旧草稿失效，人工接管撤销自动发送资格，不能与工具同时回复。人工修改的消息需要预览并明确发送。

仅本次处理、生成本店候选、建议更新共用知识分别选择。特殊优惠默认只限原会话或订单，不能自动推广。售后完成记录对应原问题；之后的新售前可以恢复，但不能解除其他暂停，也不表示退款到账。

## 七、漏答卡片

来源包括知识缺失／错误／过期、商品关联失败、重复追问、人工改判、平台数据缺失及媒体能力缺失。卡片保留原问题、上下文引用、已回复内容、具体缺口、顾客当前状态、频次、负责人和处理记录。

按相同范围、商品、意图及缺失字段聚合，保留每条证据。不同店铺规则、不同商品不能只因问法相似合并。语义误判、平台读取和媒体问题不能靠添加标准答案掩盖，应进入纠正回归或开发排查。

待处理 → 补充中 → 待复测 → 待发布 → 观察中 → 已补全。上传资料、生成草稿和关闭提醒都不等于补全；需要原问题和相邻边界复测、发布、有效检索及对应新会话证据。模拟、草稿、真实发送分别记录，无真实证据保持观察。不适用、转开发和已补全分别统计。

## 八、持续学习与版本管理

授权可信商品字段可按同步策略更新；新政策、优惠、额外承诺，以及从聊天提炼的知识，经过核对、评测和发布再生效。默认采用检索增强的知识更新，避免频繁模型训练。

候选先脱敏、归因和去重；复测覆盖原问题、口语、否定、指代、换款、多意图、售后、过期和缺资料。离线与真实模型结果分开。发布显示差异、影响范围、冲突和证据，原子切换，关联旧草稿失效；可以审计和回退。

## 九、成交优化

先保证问题解决、事实准确及售后边界，再按顾客用途、预算、兼容性和库存进行授权推荐。商家可配置语气、推荐重点和允许的引导动作；系统不能为成交虚构优惠、库存紧张或到货保证。

统计普通咨询解决率、事实错误、售后漏转、重复追问、人工改判、漏答补全、时延和成本。成交需可靠关联真实支付、取消及退款；没有继续追问或聊天说“下单了”不算成交证据。样本不足和归因不明显示未知，比较策略要考虑店铺、活动和流量变化。

## 十、架构与可靠性

模块包括桌面、店铺权限、平台连接器、会话状态、知识检索、回复校验、人工及补全、学习发布、效果与运行记录。后台独立运行，每店独立队列、会话顺序处理、跨店公平调度与限额。

主要对象：Store、Message、ConversationState、Knowledge／Revision、ProductMapping、Decision、Draft／Delivery、Override、Gap、Handoff、Candidate／Evaluation、Outcome。对象带范围、来源、版本和必要审计字段。

连接器分别报告登录、身份、接收、可信消息角色、商品／订单／物流、发送、回显和平台转接能力。不支持返回不可用。发送前再核对账号、顾客、最新消息、人工状态和知识版本；输入框清空不是发送证据，未知结果不盲重试。

关键任务持久化、幂等、可恢复。密钥本机加密；候选、日志和模型请求按必要范围脱敏，资料文本不能越权指挥工具。发行包不携带店铺、聊天、凭证和接待权限；升级先备份并保留商家资料。

## 十一、开发阶段

| 阶段 | 内容 | 完成依据 |
|---|---|---|
| P0 | 知识、改判、卡片、复测、发布和回退 | 走通闭环，隔离有效、旧草稿作废 |
| P1 | 多平台添加、登录入口、统一工作台及首店验证 | 可添加真实店、核对身份并完成受控收发与接管 |
| P2 | 三平台分别联调、同时在线及故障隔离 | 实际消息与回显、多会话、重连和长时间证据 |
| P3 | 授权资料更新、历史候选、聚类及失效管理 | 来源可查、影响可见、能发布与回退 |
| P4 | 真实订单关联、授权策略、正式交付 | 指标口径清楚，目标机器及目标并发通过验收 |

复用现有发送保护、上下文、回执、待办、知识版本、文件同步及安装能力，避免为新页面重做可靠性基础。

## 十二、验收与当前边界

分别覆盖跨店不同价、同名顾客隔离、口语和纠正、多商品多问题、售前政策与售后区分、退款追问、未知卡片、普通咨询缺资料、生成中改判、特殊优惠、过期冲突、发布回退、售后再次发生、待办恢复、断线切号、回显迟到和多平台同时接待。

离线、本机界面、真实模型构造场景和真实店铺分别报告。跨店误发、错误收件人、未经授权承诺、未知结果自动重试及售后误处理，发现后必须修复并复验。真实解决率等目标在取得标注样本和业务基线后确定，不虚构准确率。

目前三平台真实整体验收、千牛逐条身份、完整商品与实时订单物流、媒体及平台原生转接仍需逐项补齐。阶段性代码和界面通过不等于直接登录三平台即可正式使用；本机售后待办也不等于平台已经转接。
