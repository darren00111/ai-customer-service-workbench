# P0：知识与改判闭环（2026-11-02）

依据《多平台店铺工作台与知识库闭环开发说明书 v1.0》第十一节 P0 开发。本轮只使用构造店铺和离线规则验证，没有连接真实平台，也没有向顾客发送消息。初稿版本为 1.9.0-preview；本次复核修订为 1.9.1-preview，构建与安装情况以验证记录为准。

## 新增能力

### 1. 问题卡片（说明书 7.1–7.3）

源码：`app/service/gapcards.py`。卡片保存在各店独立的 `knowledge.sqlite3`（表 `gap_cards`、`gap_evidence`、`gap_events`），因此跨店不会串库。

- **来源**：每一轮保存的接待都会检查缺口；人工改判选择“生成本店知识候选”时也会建卡。
- **类型**：知识缺失、知识错误／过期、商品关联、语义误判、平台数据缺失、媒体能力缺失。顾客侧条件（收货地、预算、使用日期、未指明商品等）只在会话里补问，不生成卡片。
- **聚合**：同一商品、同一缺失字段的问题合并为一张卡（“黑杆什么材质”“黑杆的材质是什么”算一张）；问法类缺口按“商品 + 规范化问题 + 意图”聚合；商品关联按平台商品编号聚合。合并操作拒绝不同类型、商品或平台商品，每个原会话的证据都会保留。
- **状态**：待处理 → 已分配／补充中 → 待复测 → 待发布 → 观察中 → 已补全；另有不适用、转开发、已合并。不适用和转开发必须填写原因。三者分别统计。
- **完成条件**：
  - 补充资料、关联已有问答或修正商品映射只会生成**候选版本**，卡片进入“待复测”。
  - 复测时用候选版本回放原问题，也可以加入代表性变体和边界用例（例如“白杆什么材质”不能答成枫木）。候选资料不会进入正式检索。
  - 卡片关联的版本在复测通过前**禁止发布**；复测后如果其他资料发生变化，需要重新复测。
  - 发布后再用生效资料检索一次，卡片进入“观察中”；只有**新的会话**按新资料答上同一问题，且取得匹配的实际发送回显，才变为“已补全”。原会话的后续追问不算。
  - 观察来源会被标注；模拟试聊和未发送草稿保持“观察中”，注明“尚非真实接待效果”；不会计入已补全。
  - 发布后同类缺口再次出现会重新打开卡片；版本被回退时，依赖该版本的卡片也会重新打开。
- **限制**：语义误判、平台数据缺失和媒体能力缺失不能通过“补充资料”关闭，只能纠正意图并加入回归，或转开发。
- **兼容**：原有纠错→回归→启用的流程发布后，匹配的问题卡片会进入“观察中”。旧的 `knowledge_tasks`、`gaps` 表和接口保留；界面上原来的“已补充并核对”按钮已移除，因为它会让卡片绕过复测直接关闭。

### 2. 人工改判（说明书第六节）

源码：`app/service/overrides.py`、`Workbench.override()`。

- 可纠正意图、商品归属、事实与答案、后续动作，并记录原因（理解错误、知识缺失、资料过期、冲突、平台读取错误、表达不合适）和操作者。
- 改判立即作用于当前会话：只修改被纠正的条件，其他已确认条件保留（例如改了商品，收货地仍是湖南）。
- 平台会话根据接待记录自动关联，不必手填；填写核对编号时必须与原记录一致。改判清空草稿并递增 `context_revision`，生成中的旧草稿和自动任务因此不能保存或发送。有效人工修正按对应消息持久保存，重建对话及重启后仍可使用，后续明确换款仍可正常切换。
- 选择“人工接管”后，该会话不再生成可发送的自动回复。
- 作用范围：
  - **仅用于本次**：不进入知识库。
  - **生成本店知识候选**：生成回归案例和问题卡片，仍需审核、复测、发布。
  - **建议更新共用知识**：只记录建议。
- 一次特殊优惠或承诺**只能**选“仅用于本次”。
- 保存改判不会发送任何消息；修改后的回复只做预览并暂停该会话自动接待。恢复操作只解除人工暂停，不解除其他异常暂停。

### 3. 发布记录与回退（说明书 4.3、8.2）

- 每次发布和回退都写入 `publish_log`，内容包括类型、原版本、新版本、动作、操作者、原因和时间。
- `KnowledgeStore.rollback()` 只能恢复曾经生效的版本，并且必须填写原因。
- 回退后资料版本号改变，尚未发送的旧草稿会被现有的版本校验判为过期；已发送的历史回复不会修改。
- 重复启用当前版本不再重复记账。

### 4. 知识有效期

- 常见问答支持 `effective_from`（生效时间）和 `expires_at`（失效时间）。
- 尚未生效或已过期的条目不再参与回答、冲突判断，也不会作为模型的候选问答。
- 精确命中已过期的问答时，按“知识错误／过期”生成卡片。

## 工作台

位置：“接入与试聊”窗口。

- **答复纠错与回归**：新增“人工改判”表单和“问题卡片”面板。面板包括摘要、详情（原问题、工具已回复内容、缺口、复测结果、处理记录）和所有卡片操作。
- **店铺资料**：新增“发布记录与回退”。

新增接口：`list_cards`、`get_card`、`card_action`、`record_override`、`list_overrides`、`publish_history`、`rollback_knowledge`。

## 验证

- `tests/selftest_p0_loop.py`（7 组，全部通过）覆盖以下场景：
  - 构造店铺走通“漏答 → 补齐 → 复测（含边界失败与通过）→ 发布 → 新会话再回答”；
  - 只补资料不算补全、复测前不能发布；
  - 跨店不串库；
  - 回退需要原因并留痕，回退后答案恢复缺口、卡片重开；
  - 资料更新后旧草稿作废，改判作废草稿并拒绝生成中的旧任务；
  - 特殊优惠不能写成本店政策，商品改判保留其他条件，人工接管后不可自动发送；
  - 未关联的平台商品卡片不编造价格，映射、复测、发布后新会话可回答；
  - 不同商品拒绝合并，过期／未生效问答不引用；
  - 不适用、转开发、已补全分别统计。
- 原有 20 个离线自测全部通过。
- `selftest_workbench_browser` 的界面检查前 66 项全部通过，其中包括新的卡片检查。之后的步骤因开发环境未带图标文件而停止，需要在本机复跑。

## 尚未完成

- 证据都是离线构造数据，不代表真实模型或真实店铺效果。真实模型复测可在卡片上勾选后运行。
- 改判后的人工回复目前只做预览，没有接入发送；真实发送仍走原有的 `send_live_draft` 保护流程。
- “建议更新共用知识”只做记录，还没有和共用商品的确认流程打通。
- 媒体能力缺失卡片目前只能由人工改判或接口创建，平台适配器尚未自动上报。
- P1–P4（多店工作台首店验证、三平台真实验收等）不在本轮范围内。


## 1.9.1 复核修订

复现报告见 `verification/update-review-p0.md`，原始构造场景证据见 `verification/update-review-p0-probes.json`。报告中的三个问题在本次修订中分别增加了自动会话关联、按消息保存并回放修正、按对应字段事实及发送回显确认补全。原始报告保留为修复前证据。

P0 测试由 7 项扩展到 14 项，并加入正式总回归入口。新增覆盖默认人工接管后不能发送、生成中的旧任务被撤销、跨会话改判拒绝、商品修正跨重启和追问保留、顾客新换款生效、长度回答不关闭材质卡、手动回复只预览，以及实际回显后才补全。这里的“实际回显”单元测试使用构造的平台连接器，不代表真实店铺已经验收。
