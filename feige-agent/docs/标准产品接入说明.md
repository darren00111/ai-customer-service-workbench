# 标准版接入说明

## 产品边界

当前交付保留飞鸽网页客服适配器，1.7 新增淘宝／天猫、拼多多、小红书店铺的资料账户、试聊、共用商品属性及导入文字会话草稿；后三个平台尚未接入真实消息收发，不能只改网址就接入。通用能力包括多店隔离、信息咨询分类、按已核准事实生成答复、人工待办和运行状态展示；飞鸽继续使用既有会话扫描、发送确认与去重。订单修改、退款、支付仍需平台接口或人工处理，不保证物流实际送达。详见[多平台接入与淘宝联调](多平台接入与淘宝联调.md)。

## 唯一配置入口

每个客户维护 `merchant.yaml`：源码目录位于 `feige-fashion-customer-service/data/stores/<store_id>/`，打包版位于 `knowledge/stores/<store_id>/`。小商品目录可直接写在 `catalog.products`；大量商品可放在同目录 `products/*.yaml`。系统会自动发现新客户，不需要编辑 `stores.json`。已有旧店铺仍可使用原来的 `stores.json` 与 `store.yaml`。

源码环境执行 `python run.py merchant-init your_store --name 您的店铺名称` 会选择未被其他店铺占用的配置端口，并生成安全的初始配置。打包版可复制随包提供的 `merchant-template.yaml` 到上述位置，并把 `store_id`、目录名、`profile_dir` 和端口改成该店铺自己的值。多店的端口、浏览器 profile、知识库与运行数据必须互不混用。

先填真实商品、发货地、发货时效、承运商、下单流程和支付方式。只填商家已经确认的事实；空字段不会自动编造答案。商品别名用于匹配顾客常用简称。`business.synonyms` 可将客户的口语或简称映射到标准词，例如 `台球棍: 台球杆`；未配置的模糊商品名称只追问，不凭相似度猜商品。可用 `business.intents` 改写意图关键词或增加固定问答；售前政策可以放入 `business.policies`，新增意图以 `policies.<名称>` 作为数据源。`business.handoff.keywords` 定义必须交由人工的范围。商品类目仅是可配元数据，不会触发女装专有逻辑。

物流按发货时间、发货地、承运商和目的地预计时效分别回答。需要省份时效时，在 `shipping.delivery_by_region` 中填写省份映射；顾客未说明省份会先追问。普通议价只说明公开活动；批量特殊报价及额外让利进入人工待办。无货和下架会告知已知状态。商品价格、库存和地区时效可写为 `{value, source, updated_at, expires_at}`，到期后不再引用该事实。静态字段也可直接写值，但系统无法判断它是否过期。

在源码环境执行 `python run.py merchant-doctor your_store` 检查结构、商品与端口冲突。配置完成后先保持 `auto_send: false` 试运行，再由客户确认后设为 `true`；修改配置后重启桌面程序或该店铺实例以重新加载。如果商品目录为空或包含样例数据，自动发送会拒绝启动。打包版从空店铺注册表和空知识库开始，不携带开发店铺、浏览器 profile 或聊天日志。

## 可定制维度

| 配置区 | 可设置内容 | 默认行为 |
| --- | --- | --- |
| `platform` | 飞鸽地址、浏览器、端口和独立 profile | 飞鸽官方工作台地址；自动查找浏览器 |
| `automation` | 启用、自动发送、启动行为、扫描频率、全量补扫间隔、每分钟上限 | 自动发送及自动启动关闭；全量补扫默认 15 秒 |
| `business.category` | 店铺类目说明 | 空，待商家填写 |
| `business.handoff` | 售后、投诉及特殊人工分流词 | 常见售后词转人工 |
| `business.shipping` | 发货时间、发货地、快递和分省预计时效 | 空事实不自动回答 |
| `business.orders` / `payment` | 下单流程、支付方式 | 空事实不自动回答 |
| `business.intents` | 意图关键词、数据源和核准固定答复 | 内置通用信息意图，缺参时定向追问 |
| `business.synonyms` | 口语词、商品简称到标准词的映射 | 内置少量通用口语词；商家专有词为空 |
| `catalog.products` | 商品 ID、标题、别名、价格、库存及自由属性 | 空目录；不使用示例商品 |

运行时优先响应侧栏变化和未读会话，另以 `automation.full_scan_interval` 周期补扫；没有新消息事件时会回退到定时扫描。页面控制权按会话释放，不再整轮持有；但单次会话的发送及确认仍需独占页面。一个消息包含多个已识别的信息意图时，会逐项核对后合并回答；其中任何一项涉及人工风险或缺失事实，就不会把整条消息当作完整可自动答复。此能力是规则匹配加可配置同义词，不是通用语义模型。库存、价格和物流配置目前是客户维护的快照。需要实时准确性时，应另行接入商家授权的数据源；在未接入前，请不要把可能变化的时效或价格写成保证性承诺。人工待办按消息去重，后续独立的信息咨询可以继续回答；发送结果不明时整个会话仍暂停，以防重复发送。上线前应使用该客户真实聊天样本验证覆盖率、误判率、人工分流情况和实际响应延迟。
