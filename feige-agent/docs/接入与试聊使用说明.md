# 接入与试聊（1.6.0-preview）

本版新增“店铺接待与持续学习”：商家可设置接待目标、语气、推荐重点，保存后下一轮生效并可回退；纠错自动生成候选，支持真实模型回归，成交结果按来源、会话和经营条件整理。详见随包的《持续学习与成交优化说明》。真实平台接口仍待授权接入，不承诺实际成交率提升。

本版已接入阿里云百炼千问模型，默认 qwen3.8-flash。模型结合最近对话、会话状态、本店商品名称、属性内容和FAQ索引理解问题；商品事实和答复仍来自本店已启用资料。
真实模型的构造场景验收不等于真实商家准确率。未启用模型时，仅使用有限离线规则验证流程。

## 千问设置与试用

1. 在窗口顶部展开“千问模型设置”。填写模型名称、百炼官方接口地址和自己的 API Key。已有配置时密钥留空保持原值。
2. 北京地域的新版专属地址为 `https://业务空间ID.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`。从百炼模型详情页的官方代码示例复制实际地址，不要把业务空间ID占位文字直接填入。
3. 勾选启用并保存本机配置，再点击“验证连接”。“待验证”仅表示尚未在当前进程成功调用；只有成功调用后才显示“已验证”。
4. 在模拟店铺试聊，查看“本轮理解与回答依据”中的模型、意图、依据和耗时。试聊不发送到飞鸽；启用模型时，对话、当前店铺商品与问题索引会发送给百炼。

密钥通过 Windows DPAPI 按当前用户加密，保存在 `%LOCALAPPDATA%\FeigeCustomerService\qwen.json`，不回传给界面，不写进源码或发行包。该文件不要复制给客户；客户应在自己的电脑配置自己的密钥。更换 Windows 账户后需要重新填写。
同一用户的源码和桌面程序共用此配置。修改后下一轮生效；调用期间配置变化会取消本轮结果。
取消启用恢复离线试聊，同时新版引擎会停止自动发送。认证、网络、限流或结构无效时不切回规则自动发送，也不冒充模型已成功。
当前不自动重试失败请求，避免重试风暴；网络调用超时30秒。单次最多发送10万字符上下文、输出1600 tokens，超出限制会停止本轮。
qwen3.7 / qwen3.8 系列使用严格 JSON Schema 并在本地再次校验；其他千问名称使用 JSON 模式与同样的本地校验，需自行验证接口兼容性。

模型负责识别简称、同义表达、纠正、指代和多意图，并可将自然问法对应到已有FAQ的标准问题。随后仍检查商品范围、资料版本和有效期；模型不能直接提供价格、库存或政策正文。当前FAQ索引每次最多80条，商品与对话总量受单次上限约束，大型店铺还需扩展向量检索。
官方接入依据：[首次调用](https://help.aliyun.com/zh/model-studio/first-api-call-to-qwen)、[结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。

## 本版新增：上下文与学习流程

- 会话摘要由已确认的商品、地区、预算、使用日期和待解决问题生成，每项带原文引用。近期保留24条消息供理解；完整原文另行归档，可每100条向前翻页。
- 试聊会话状态和原文落盘。工作台重启后，同一会话标识可续接；“开始新会话”使用新的独立标识。
- 可试问 `两百以内推荐一根`、`黑杆和白杆比较一下`、`寄湖南，周五比赛来得及不`。推荐和比较仅依据可核实的价格、库存；不会推断未提供的性能。
- 支持今天、明天、后天、周五、下周一和具体日期；到货判断按店铺日期加备货、运输天数计算，明确表达范围和风险。默认店铺时区为 Asia/Shanghai，可在政策中设为 Asia/Seoul 或 UTC。天数按自然日计算；工作日、节假日、截单时间和不完整时效资料不会凭空补齐。
- `预算200以内`、`预算100到300元`、`预算200` 和 `预算不限` 可作为筛选条件；“一百五”等有歧义口语会要求确认。提供模型后再验证更广泛的表达。
- 本地检索展示词形相似候选；启用千问后还会在已核准FAQ索引中选择语义相同的问题。候选本身不能直接充当答案，仍需核对版本、有效期和商品范围。

## 持续更新本地商家资料

在“资料持续更新”中选择明确授权的本地 JSON 或 CSV 导出文件，选择类型及“增量合并”或“完整替换”。
工作台打开期间会定时检查，接待引擎在处理新消息前也会检查到期来源；关闭整个应用后不会运行系统后台服务。
检查间隔为10–86400秒。可暂停和恢复单个来源，也可立即检查。文件未变时不会重复生成版本；读取或校验失败时保留当前生效资料并显示错误。

默认变化只生成待确认版本。仅商品来源允许在明确勾选可信来源后自动启用；店铺政策、FAQ及历史候选仍需核对。
商品增量以 product_id 合并顶层字段、保留其他商品。字段中的对象或规格列表作为整项更新，不会猜测其内部差异。删除必须显式提供：

```json
{"upserts":[{"product_id":"A01","stock":5}],"delete_ids":["A02"]}
```

店铺政策支持嵌套合并；FAQ按问题与商品范围合并。增量候选若基于旧版资料生成，启用时会拒绝覆盖新的更新，需要重新生成。
这是一条已完成的本地资料同步流程，不等于已接入飞鸽商品中心或订单接口。

## 人工纠错、回归和补资料

1. 在“答复纠错与回归”选择一次本店接待，填写正确动作和答复必须包含的内容，保存案例。
2. 一般未知问答可生成候选知识，保留已有问答。价格、库存和售后动作纠错会提示更新相应资料或规则，不允许用FAQ掩盖业务事实。
3. 预览候选，点击“回归验证预览版本”。测试在隔离的版本视图中运行，不临时切换线上知识。
4. 全部启用中的案例通过后，再核对内容并启用。验证后其他依赖资料发生变化，需要重新测试。
5. 通过回归并启用的纠错会自动完成同一问题、同一商品的资料任务。其他任务可在核实补全后手动标记完成。

经营政策改变时可停用已过时案例，原记录保留。可导出可复制的回归案例，包含上下文、基准日期、预期动作和答复片段，供后续不同模型评测使用。
日期案例固定到原接待日期，避免“明天”随测试日期变化。回归通过表示满足这些已有案例，不代表真实中文语义准确率。
统计展示本地接待次数、资料齐备答复、补问及人工分流，不把它们当作已验证的客户问题解决率。

## 打开

在飞鸽客服主窗口点击“接入与试聊”。也可运行 `python run.py lab`，或用打包程序的 `--lab` 参数直接打开。
窗口内的试聊记录保存在本地，不向飞鸽发送消息，不登录真实店铺浏览器；启用千问时会调用百炼服务。

## 没有真实数据时

选择台球用品、服装或家居模拟店铺，点击示例或自行输入：

- `黑棍几钱，还有货吗`：多问题。
- `啥时候到` → `长沙`：补充目的地。
- `黑杆多少钱` → `白杆多少钱` → `前一个还有货吗`：商品切换与指代。
- `不是问哪里发货，我问什么时候到`：否定纠正。
- `还没买，想了解退货规则` 与 `我要退货`：售前政策与售后行动。
- `这根打着会不会震手`：缺少性能资料时不编造。

台球模拟店可勾选关联模拟订单。其他店的订单与物流没有连接，不能据此验证实时查询能力。
售后开始后，会话保持人工处理状态；模拟试聊可用“开始新会话”重新测试。

## 接入客户

1. 展开“接入新店铺”，填写英文标识和店铺名称。自动发送默认关闭。
2. 导入商品、店铺政策或常见问答。商品支持 JSON / CSV，其他资料支持 JSON；窗口内有格式示例。
3. 查看待启用版本的完整内容，核对后勾选确认并启用。
4. 试聊并查看理解结果、资料依据和缺失字段。根据资料缺口补全知识。
5. 登录飞鸽、验证模型连接并完成本店真实聊天验收后，再开启实际自动接待。

商品导入是完整列表替换；应包含仍在售的全部商品，不能仅上传一件变更商品而期待其他商品保留。
启用新的店铺政策版本同样替换整份已发布政策。历史版本保留，可选择、预览、确认后恢复。
导入失败不会替换正在使用的版本。库存与价格是资料快照；需实时准确性时还要连接授权业务数据源。
可为字段填写 `value/source/updated_at/expires_at`；过期资料不会用于回答。
同一商品有多个规格时请提供 `variants`：

```json
[{"product_id":"TEE","title":"棉T","aliases":["短袖"],"price":89,"stock":12,"attributes":{"材质":"棉100%"},"variants":[{"sku_id":"B-M","color":"黑色","size":"M","stock":0,"price":89}]}]
```

## 历史对话与学习

历史导入会合并连续的顾客消息、连续的客服答复，形成待审核 FAQ，保留原会话及消息位置引用。该过程不训练模型，也不能判断原答案是否正确。
手机号、邮箱、长数字编号和带标签的地址会进行基础替换；这不是完整的隐私识别，应先自行脱敏原始导出。
答复相隔多轮、特殊承诺或过期优惠，需要在导入前整理，或修改候选内容后重新导入。
依赖“这个”“前一个”等上下文的问答，在未限定商品时不会作为全店通用回答。历史候选不会自动上线；真正的语义检索仍待模型服务接入后验证。

知识文件位于 `data/reception/shops/<store_id>/knowledge.sqlite3`；演示资料位于 `data/reception/demo/`。
会话状态、知识及版本按店铺隔离。新的店铺注册默认使用自己的知识库。原有开发店铺映射不自动迁移。

## 当前能力与待接入项

已实现：多轮状态、结构化摘要与原文、预算和日期处理、限定范围口语规则、商品/地区纠正、多问题分项答复、商品筛选和事实比较、
具体资料任务、过期校验、SKU查询、售后人工状态、知识导入审核和版本回退、文件增量同步、历史候选合并、商家纠错与隔离回归、三类模拟店铺、可替换的模型理解契约。

本版新增：千问真实 API、基于上下文的语义理解、已核准FAQ语义选择、加密配置和模型连接状态、调用耗时与token计数。

待接入：大型知识库向量检索、授权商品中心自动同步、真实订单/物流查询、从店铺后台持续采集历史，
以及真实客户场景的准确率、响应时间与成本评测。当前没有授权数据来源时，不能宣称“登录后自动学完整店铺”。

## 现有店铺启用新版框架

在本店 `merchant.yaml` 的 `business` 中添加 `reception: {enabled: true}`。
新版启用后不允许跨店知识映射；模型缺失、模型判断无效或使用模拟数据时，自动发送会被阻止。
历史引擎仍保留，已运行店铺不会因升级被自动切换到新框架。新建的工作台店铺默认使用新框架。
`auto_send: false` 现在在单轮发送入口也强制生效；`--dry` 不会生成真实人工待办或修改会话状态。

## 开发接入约定

`app/service/contracts.py` 定义 `Interpreter.understand(request)`，传入原始角色对话、店铺商品候选及会话状态，
仅返回结构化意图、商品、目的地、订单候选及缺失信息。远程响应不得直接替换最终事实回复。
`SnapshotDataSource` 是本地数据适配器，后续可实现同一接口连接商家授权数据源。
订单授权列表必须由可信会话连接独立提供，顾客或模型给出订单号不能视为授权。

验证命令：

```text
python tests/selftest_reception.py
python tests/selftest_reception_pipeline.py
python tests/selftest_learning.py
python tests/selftest_workbench_browser.py
python tests/selftest_qwen.py
```

默认测试均隔离本机模型配置，不会产生API费用。显式运行 `FeigeCustomerService.exe --self-test-qwen --self-test-report report.json` 会调用当前启用的千问模型，对24个构造场景进行验收，可能产生百炼费用；不发送任何消息到飞鸽。
`--self-test-offline` 始终不调用模型。窗口中的知识回归默认离线；勾选“使用当前千问模型验证”后会产生真实模型调用，并显示 model_regression。可导出案例用于后续独立评测。
