# 持续接待开发进度（2026-11-02）

这是当前源码的开发说明。此前的 1.8.0-preview ZIP 不包含本次全部变更；本次构建尚不是三平台验收完成的正式交付版。

## 1.9.0-preview：按店全店接待与售后待办恢复

在“接入与试聊”中先连接并核对店铺，启用本店商品与政策、模型，再对指定测试顾客完成自动回复及回显确认。工具会检查回执属于当前店铺、账号、模型和资料版本；人工点击发送不算自动收发测试。满足条件后，店主可勾选开启本店全店接待，然后在主窗口启动。开启权限只对本店账号生效，不会连带开启其他店铺，也不代表平台已经完成生产验收。千牛尚未核实逐条消息身份，不能通过勾选绕过。

主窗口可以启动、停止已开启店铺，显示接待轮数、确认的自动回复数量和售后待办。开启全部只启动已经具备条件的店铺；其他店铺进入接入准备说明。关闭全店接待会使正在生成的旧回复失效；停止时会等待本轮退出再断开，不会在停止后继续发送。程序重启保留设置，但不会自动连接或接待。消息处理不受界面只显示最近 100 个会话的限制；同一远端账号不能重复绑定到两个本地资料并同时接待。

售后分类与本机待办在同一数据库事务中保存，提醒写入失败会显示异常并在后续轮询或重启时重试。重复补记不会新增相同待办，也不会重新打开已完成任务。主窗口点击“已在原平台处理”会保留人工处理记录，只恢复该售后暂停；未知发送、媒体或新的售后导致的暂停仍需分别核对。历史售后原文继续保留，但已处理标记允许后续新的售前咨询重新判断；退款后的“啥时候到”等歧义仍可识别为售后。这里的完成标记不代表退款已到账或平台转接成功。

主窗口启动接待时也运行已注册的商家导出文件同步。已核对并启用的价格、政策与知识版本更新后，后续回答采用新版本，尚未发送的同一咨询可重新生成。聊天提炼的政策、优惠和承诺仍先审核，不自动生效。成交效果仍需要真实订单结果关联验证。

以下保留此前版本的开发记录。

1.8.3-preview 在绑定后观察同一客服页已经返回的单会话历史响应，不导出请求头、Cookie 或反爬签名，也不主动翻页。原文按当前店铺身份与双方角色核实后单独保存；历史不会替代实时消息头，也不能确认发送成功。相同记录重复出现不新增；内容冲突、同刻顺序无法核实或发现实时连接缺失消息时暂停核对。长时间没有对话后，不再沿用旧商品卡片和条件。历史补齐采用独立上下文版本，模型生成期间有新历史到达时旧草稿会取消，后台任务可对同一条新咨询重新生成。

观察到的连续问答可自动生成本店的待审核版本；商品切换和未解析媒体会分开处理，避免把前一款的答案接到后一款。候选按来源去重，并脱敏个人信息和凭证字段。候选生成失败只报告学习未完成，不把历史内容当成有效经营规则。商家仍需核对、评测后启用，原有版本回退机制保持有效。它不等于全店历史已导入，也不代表真实聊天中的说法已经正确。

1.8.2-preview 修正首次拼多多登录流程：在独立浏览器的新空白页建立消息监听后才跳转客服页；登录后的身份检查保留同一目标页和订阅。登录页面尚未到达客服路径、标签页换成另一个目标或缓冲溢出时不能绑定。绑定前的消息只作为上下文，不作为新的自动回复目标；绑定前已关闭的旧连接不会误报为本轮断线，绑定后的断线仍会停止采集。复用已经打开的客服页时仍可能需要刷新一次，不能把未观察到通道视为收发就绪。

此流程已通过独立临时资料的本机浏览器、HTTP 和 WebSocket 测试；该测试没有访问真实平台。桌面上已安装的 1.8.1 主界面也通过了实际可访问文本核对，11 个店铺均保持未启动。千牛安装登记和运行窗口仍未检出；这不排除客户端在其他位置或另一台电脑。

1.8.1-preview 增加了拼多多商品咨询卡片、商品卡片上下文、字符串时间戳、已读回执和表情描述的处理。卡片只提供商品引用，价格与库存仍从本店已确认资料查询。“这个”沿用当前卡片；明确换款、“前一个”或比较按对话意图处理，切换时清除旧规格。未知或对应多个商品的卡片不会套用前款价格，也不会反复要求顾客再发同一张卡片，而是说明资料缺口并生成本店补全任务。四组真实千问调用验证使用的是构造对话，不是实际顾客效果证明。

从平台采集的商品编号与本店 product_id 相同会直接关联。使用商家内部编号时，可在商品资料的 platform_ids 中提供各平台编号，例如 {"pinduoduo":"123"}；对应关系只在本店生效。历史卡片中的价格、名称和链接不能自动改写本店商品事实。

## 已接入的开发流程

主窗口选择淘宝或拼多多店铺，点击“连接并验收”进入对应店铺。拼多多使用独立浏览器资料登录；淘宝使用已安装的千牛接待中心。登录、验证码由店主本人操作。

核对店铺与客服身份后可以持续读取消息并生成草稿。关闭“接入与试聊”子窗口不会停止主程序中的接待任务；关闭主程序会停止任务、关闭子窗口并释放连接。每个资料账户仅允许一个程序持有连接，程序异常退出后由系统释放占用。

指定顾客的自动收发检查仍只面向明确选择、已实际收到消息的测试顾客；1.9 的全店接待是单独的按店设置，流程见上文。售后进入本机人工待办；人工需要在原平台处理，目前没有实现原平台的客服转接。工具发现人工回复、消息撤回、未支持的卡片或媒体、身份变化、消息缺失或发送结果不明时，会暂停对应会话或断开连接。

千牛目前只提供兼容性检查和符合预期文本格式的预览草稿。合并文本中的“作者＋时间”可能来自顾客引用，不能证明实际消息角色。逐条作者与稳定消息标识尚未在真实客户端上核实，因此实际发送保持关闭。公开项目的控件定位只是适配线索，不能作为本机收发验收证据。

## 商品资料和持续学习

拼多多绑定后，在同一个客服页面打开商品列表或详情，再点击“读取已采集商品并预览”。工具观察该页面已经返回的资料，不导出登录信息，也不会模拟反爬参数。

采集结果生成本店的待核对版本，不自动启用、删除商品或修改政策。重复读取同一批资料不会重复新增版本；本店已确认的价格、库存和其他商品属性会保留。团购价格仅保存为有时效和明确说明的区间属性，不会转换成所选规格价或个人最终支付价。规格名称不等于该规格有货。页面返回部分商品，也不等于完成全店同步。

本地资料文件仍可注册增量同步；核对并启用的商品、问答与政策版本会影响后续回复。历史聊天和人工纠错提炼候选，经过回归评测与审核后启用，可回退版本。

真正确认发出的回复会更新对应接待记录。发送回显迟到、接待任务重启或学习写入被中断时，工具通过持久回执补记，不重复发送。没有确认的发送、模拟会话和预览草稿不计为自动解决；人工审核发送不计为自动接待。成交优化还需独立核实并关联真实订单结果，回复数量不是成交提升证据。

未知发送需要先在原平台核对、人工处理，再在会话中确认“记录人工处理并关闭本轮”。这会保留核对记录，允许后续新咨询继续接待，永远不会重发本轮旧回复，也不会把本轮标成发送成功。新消息已有其他暂停原因时，关闭旧发送不会解除该暂停。

## 仍待真实店铺完成

- 淘宝：核对本机千牛版本与逐条消息结构，完成可靠接收、发送回显、多人会话切换及长时间运行。
- 拼多多：核对真实身份接口、新版二进制消息与商品响应字段；补齐商品卡片、图片、订单、物流、断线补齐及原平台转人工能力。
- 抖店：在 Edge 登录真实飞鸽并验证接收、发送、人工接管和断线恢复。
- 三个平台分别验证真实商品更新、人工纠错、知识版本回退及真实订单关联，再逐店开放正式自动接待。

当前所有离线和本地界面测试使用构造数据，没有向真实顾客发送消息，不能据此宣传三平台已开箱可用或已经提高成交率。
