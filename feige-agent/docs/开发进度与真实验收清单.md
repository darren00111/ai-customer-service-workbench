## 下一轮真实店铺验收顺序

### 第一步：只读身份与消息

先选一个可用于测试的真实店铺。淘宝按当前条件使用千牛桌面接待中心；抖店使用 Edge 飞鸽；拼多多使用本店独立窗口。

核对平台、店铺、客服、顾客、双方消息角色、稳定消息标识、时间顺序和商品卡片。切换顾客、切换账号、重复历史与连接中断时，都要能发现并避免混淆。该阶段不自动发送。

### 第二步：事实与草稿

接入并核对本店商品和经营规则，用真实样本验证口语、纠正、多问题、商品切换和售后分流。确认每个关键结论有有效依据，缺资料进入正确卡片，售后进入人工待办。

### 第三步：受控收发与人工操作

仅指定测试会话验证单次发送和匹配回显。覆盖新消息取消旧稿、人工接管、未知发送不重试、售后完成后新咨询、再次售后、掉线重连、重启和迟到回执。

### 第四步：多店并发与学习效果

首店稳定后，逐一增加第二店及另一个平台。验证不同店价格政策隔离、视图切换不串话、一家异常不拖停其他店。商定目标机器、店铺数、消息负载和持续时间，再做容量验收。

使用真实纠错和漏答完成补资料、复测、发布、新会话观察和回退；成交评估必须使用可靠关联的真实订单，不能以回复数量代替。

## 验证边界

工作台测试中的平台登录调用被拦截；平台连接器、模型和回显构造测试不证明真实店铺效果。发布记录、使用说明和验收报告都应保留这一边界。

没有实际验收证据时，production_verified 保持 false。千牛当前逐条消息作者与稳定标识尚待真实客户端验证，实际发送继续关闭。新增平台入口不会改变这项限制。
