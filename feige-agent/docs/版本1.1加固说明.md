# 飞鸽客服 1.1 加固说明

当前版本 1.1.2 是 1.0.0 之后的稳定性加固版，不改变 1.0 的知识库和客服决策范围。

## 本版完成

1. 页面控制权统一：后台扫描、立即检查、人工草稿发送和页面探测共享店铺级可重入锁；会话切换、复核和发送按完整事务串行。
2. 可靠去重：页面能提供平台消息 ID 时优先用它生成 24 位 SHA-256 指纹；取不到时兼容原有可见消息特征；升级后继续识别 1.0 的旧指纹。
3. 发送结果处理：输入框清空不再等同于成功。只有出现内容一致的新客服气泡才确认送达；点击后的未知结果持久化为 `delivery_unknown`，禁止自动重试。
4. 运行数据保护：会话状态使用临时文件、刷新磁盘、原子替换和已知良好备份；主文件损坏时自动读取备份。人工待办追加时刷新磁盘，重写前保留备份和无法解析的原始行。
5. 页面异常恢复：Chrome 启动时等待飞鸽目标页；若连接误绑到临时页，监督器会重新枚举标签页、重建连接并恢复监听。
6. 累计回复统计：总览、店铺列表和详情读取持久化累计值，并单独展示本次运行回复；应用重启不会清空历史统计。

## 验证边界

- 自动测试覆盖页面租约串行、真实浏览器模拟页的发送气泡确认、结果不明不误报、跨重启占用、1.0 指纹兼容和损坏恢复。
- 真实店铺仍需按“先一个店铺、再十至十五店”的顺序验收。单店验收应同时覆盖人工操作、后台接待、浏览器掉线重连和长时间运行。
- 本版不替换飞鸽原生聊天界面。统一工作台的上下文草稿和待办排序放在真实多店验证之后。

## 结果不明时的处理

状态摘要中的 `delivery_unknown` 大于零，表示系统已经执行过发送点击，但没有观察到对应客服气泡。此时系统不会自动重发。操作员应打开对应飞鸽会话核对：若消息已存在，标记待办完成；若未发送，应先解除该会话的待核对状态，再人工发送。
