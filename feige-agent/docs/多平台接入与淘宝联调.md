# 多平台资料准备与淘宝客户端联调

本文记录 1.7.0-preview 的资料准备阶段。1.8.0-preview 已增加拼多多网页连接联调和千牛只读兼容检查，最新状态与操作见 [GitHub 调研与连接联调](GitHub调研与连接联调.md)。淘宝会话收发仍待适配，两个平台均未完成真实店铺验收。

原记录日期：2026-10-20。用户已选择淘宝／天猫作为首个新平台，日常使用千牛桌面客户端，目前只有店铺／千牛账号。

## 当前能做什么

| 平台 | 建立资料账户、试聊、导入文字会话草稿 | 实际消息接待 |
|---|---|---|
| 抖店飞鸽 | 支持 | 保留现有网页适配，真实店铺仍需验收 |
| 淘宝／天猫 | 支持 | 千牛客户端待联调；尚无实际收发连接 |
| 拼多多 | 支持 | 待接入 |
| 小红书店铺 | 支持 | 待接入；不等于账号私信或小程序客服 |

平台状态来自程序内实际连接能力。创建资料账户、登录平台或通过试聊，都不表示真实消息已接入。所有新店自动发送默认关闭。非飞鸽店铺不能通过主窗口、全部启动、CLI 或直接调用飞鸽运行器误启动。

## 给多平台商家的操作方法

1. 从桌面打开“抖店智能客服”，点击“接入与试聊”。在“接入新店铺”选择平台，填写店铺标识、名称、商家标识和品类。
2. 同一商家的多平台店铺填同一商家标识（例如 `brand_a`）。不同商家分别填写。店铺标识在本机必须唯一，建议 `brand_a_tb01`、`brand_a_pdd01`。
3. 在各店导入并启用自己的商品及政策。价格、库存、运费、优惠、发货时效、售后政策不共用。
4. 在“同款商品关联与共用属性”填写商家内部商品标识、属性 JSON 及出处，核对后保存。共用版本只对该商家分组可见。
5. 选择本店商品与共用版本，明确确认同款后生成待启用版本。系统补充缺失属性，保护本店已有属性；在“店铺资料”预览全文后启用。
6. 共用属性更新会生成新的不可变版本。重新关联到各店并审核后生效，可按店回退；没有跨店自动发布。之前从共用版本继承且未被本店改写的属性可更新或移除，本店人工覆盖优先保留。

本版关联到商品级别；价格和 SKU 规格保持原店数据。SKU 对应关系、跨店 FAQ 发布、全平台实时统一收件箱和商家员工权限系统是后续工作。本机商家标识是资料分组，不是云端登录权限；当前本机操作者可管理所有分组。已有使用记录的店铺若变更平台或商家归属会被拒绝，需要新建资料账户，避免历史数据混用。

## 导入会话检查

格式如下，消息按时间排列；各条消息必须有稳定的标识。当前只支持文字消息，不会读取任何平台账号密码。

```json
{
  "store_id": "brand_a_tb01",
  "conversations": [
    {
      "conversation_id": "conversation_001",
      "messages": [
        {"message_id": "m1", "role": "buyer", "content": "我看看黑色台球杆"},
        {"message_id": "m2", "role": "agent", "content": "想了解哪方面？"},
        {"message_id": "m3", "role": "buyer", "content": "几钱"}
      ]
    }
  ]
}
```

- 每次文件限5MB、200个会话、合计3000条消息，每会话最多1000条；导入前移除无关个人信息。
- 相同消息重复导入不重复新增。消息标识不变而内容变化，或新增消息插入已有时间顺序中间，会拒绝该次导入；所有会话作为一次事务导入。
- 商家、平台、店铺、会话共同确定范围；同名顾客和相同消息标识不会跨店合并。
- 草稿结合最近24条原始双方对话，并从已有顾客消息重建条件；已核准的商品、政策仍是事实来源，历史客服答复不会成为新政策。历史文本里的订单号不能授予订单查询权限。
- 售后识别为人工处理后暂停本地草稿。需在原平台实际接待；这不是平台转人工成功通知。
- 有新消息或人工暂停时取消旧草稿。生成的草稿可在本店接待记录中纠错、回归，但不会记成已发送或真实成交接待。

## 淘宝接下来的联调

目前只有店铺／千牛账号，因此第一步是确认千牛桌面客户端的可读信息与操作能力。开发时尚未检测到运行中的千牛窗口，未读取真实客户对话，也没有发送消息。

需要商家打开并自行登录千牛客户端，保留一个用于验证的客服会话。检查顺序为：

1. 确定客户端版本、店铺和客服子账号，以及能否可靠识别当前会话、买卖双方角色、最新消息和商品卡片。
2. 只读采集与本店资料查询，核对顺序、重复事件和多个同名买家。
3. 生成草稿，与人工答案核对；验证售后待办及人工接管时暂停自动行为。
4. 在明确指定的测试会话中验证发送与确认，确保新消息打断旧草稿，未知结果不自动重发，且不会错店错客。
5. 验证后台运行、切换会话、断线、重连和长时间接待，通过后才允许单店小范围自动接待。

客户端若无法提供稳定的读取、发送确认或后台接待能力，则先交付辅助草稿模式，继续评估官方客服机器人或千牛插件接入。不将仅仅能在前台点按钮的方案标为稳定的多店后台自动接待。

## 官方接口调查与证据边界

- 淘宝官方有[客服机器人类目规则](https://developer.alibaba.com/docs/doc.htm?articleId=121757&docType=1&source=search&treeId=253)。类目存在不代表当前账号可调用聊天收发接口。
- 官方列有[机器人智能辅助账号订阅状态查询接口](https://developer.alibaba.com/docs/api.htm?apiId=49454)，需要授权。本次没有用户应用凭证，没有核实到当前应用的权限列表，不能据此实现或宣布接口已接通。
- [旺旺聊天记录接口升级公告](https://developer.alibaba.com/support/announcementDetail.htm?id=25584&source=search)是2021年的历史公告，说明旧接口发生过升级，不能把旧接口、旧申请条件当作当前已获权限。
- 千牛工作台提醒、模板消息或任务消息接口，不等同于买卖双方聊天收发。后续只按实际获批的接口文档实现，不根据相似名称猜测接口。
- 小红书[小程序客服消息](https://miniapp.xiaohongshu.com/doc/DC897608)和[电商开放平台](https://open.xiaohongshu.com/document/developer/file/33)是不同场景。拼多多实际客服接入权限本次尚未核实。

## 存储与升级

现有店铺 ID 和数据路径保持兼容，缺少平台字段的旧店默认飞鸽，缺少商家标识默认 `local`。新增的共用商品、关联、会话范围与导入消息保存在 `data/reception/multichannel.sqlite3`，各店原有知识库仍独立保存。升级程序保留整个 `data` 与 `knowledge`，发行包不含任何真实店铺、登录资料、对话或密钥。

千问传输优先直连已校验的百炼官方 HTTPS 地址，直连发生网络故障且系统配置了代理时再尝试一次系统代理。认证、限流、服务端错误和重定向不会重试；证书校验与禁止重定向继续生效。本次修复的是本机代理关闭 TLS 连接、而直连正常的问题，不修改系统或浏览器代理设置。
