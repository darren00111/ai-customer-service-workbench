# 店铺持续学习与成交优化 · 1.6.0-preview

本版把商家需求、接待回复、纠错和成交结果连成可追溯流程。已经具备接收真实业务数据后的学习接口，但尚未连接抖店商品、订单、物流和历史采集接口。当前不承诺实际成交率提升。

## 商家能调整什么

打开“接入与试聊 → 店铺接待与持续学习”，设置接待目标、语气、优先商品、推荐时重点说明的属性和是否提供选购帮助。保存后形成店铺政策新版本，下一轮生效；在知识版本中可以预览、回退。

优先商品必须属于本店，推荐仍先满足顾客品类、预算、有效价格和库存。优先推荐不能突破顾客条件；没有事实支持的卖点不会添加。选购引导只在已经回答清楚、有依据的普通咨询后出现，同一会话最多一次，不用于售后或资料不足的咨询。

当前自动比较的范围是两种预先允许的方式：“回答后等待”和“适时提供选购帮助”。商家设置的亲切语气和推荐重点直接生效；自动学习不会自由生成优惠、改价、承诺到货或改写售后政策。

## 怎样持续积累知识

1. 每次接待保存本店会话、理解结果、答复依据、知识版本和是否真正发送。缺资料、未知问题生成待补充任务和学习建议。
2. 商家填写正确处理方式后，系统保留为回归案例。未知问答或没有依据的详情咨询可自动生成候选FAQ；涉及价格、库存、售后动作等问题继续要求修正对应资料或规则。
3. 候选不直接发布。商家预览、运行回归，再确认启用；可勾选“使用当前千问模型验证”，检查真实语义效果。默认离线回归不会产生API费用。
4. 启用后的知识供后续语义查询使用。同义问题不必重复添加关键词。商品限定和上下文相关问答继续检查范围、版本和有效期。
5. 知识变化后，过时的候选可重新生成、重新回归。政策改变可停用旧案例；不将旧人工答复当作永久正确答案。

工作台打开时每5秒检查持续更新来源并整理学习建议；实际接待在新消息前同步资料、确认发送后整理学习记录。关闭整个程序后没有独立系统服务。日常库存或来源更新时间变化不清空成交学习；价格、商品范围、实际属性或经营政策改变后重新分组。

这条流程更新的是店铺知识、受控回复方式和可重复验证的经验，不训练或微调千问模型权重。

## 成交结果怎样进入学习

在“资料持续更新”中选择“成交与退款结果”，登记本店授权导出文件。默认只记录来源未核实的结果；只有商家确认来自本店订单后台后，才能勾选来源确认。

当前要求按以下对接格式提供JSON，而不是任意订单表格。真实平台适配器负责将本店订单映射到飞鸽的稳定会话标识；不能根据顾客说“我买了”判断成交。

```json
{
  "store_id": "my_shop",
  "coverage": {
    "from": "2026-10-01T00:00:00+08:00",
    "through": "2026-10-18T00:00:00+08:00",
    "complete": true
  },
  "events": [
    {
      "store_id": "my_shop",
      "event_id": "order-event-100-paid",
      "session_id": "本店真实会话标识",
      "order_id": "本店订单标识",
      "event_type": "paid",
      "occurred_at": "2026-10-08T12:30:00+08:00"
    }
  ]
}
```

事件类型为 `paid`、`cancelled`、`refunded`。时间必须带时区。事件标识用于去重；同一标识内容冲突、跨店数据、同一订单绑定不同会话、同一时刻矛盾状态都会被拒绝。订单号只保存按店铺计算的哈希，不能从顾客文字中生成“已核实订单”。

`coverage` 表示该时间段内的订单状态与会话归属已经核对并完整覆盖，不只是“文件生成到某日”。没有覆盖声明可以导入观察，但不参与自动判断成单效果。覆盖时间不能晚于当前时间。

退款会撤销对应订单的成交计数；事件乱序按发生时间处理。同一会话多条消息或多个订单只贡献一个会话样本。付款发生在接待之前、超出观察期或没有可靠关联时，不计作接待后的成交。

## 学习方式

- **记录问题和结果**：保留本店当前回复方式，默认选项。
- **对照比较**：在同一经营条件下，按稳定的会话分组对照两种选购引导，供商家评估。单个会话跨重启不会因日常库存刷新换组。
- **数据充分时自动选择**：在商家允许的两种方式中，根据近期90天的完整观察数据选择方式。默认每种方式至少30段会话、每段观察7天；可调整门槛，最低每组20段。两个比例的Wilson区间不重叠时才形成候选，数据不足则继续对照。

只有模型成功、回复已确认发送、使用真实资料的接待能进入成交比较。模拟试聊、发送失败、结果不明、未发送草稿、手工标记和没有完整订单覆盖的会话都不能用来证明成交提升。

从“对照比较”切换到“自动选择”可沿用相同经营条件的证据。产品价格、商品范围、属性或店铺政策改变后重新分组，保留历史记录。退款和新数据会重新计算结果，旧证据超过90天后退出当前观察。

该判断是保守的产品选择规则，不是统计显著性承诺或因果结论。进店流量、商品价格、促销、库存和季节都可能影响下单；实际效果需要真实店铺对照验证。

## 真实平台适配器的接入位置

商品和政策适配器更新现有知识版本；可信订单适配器调用 `CommerceLearning.ingest_export(payload, origin="authorized_connector", trusted=True)`。这不是公开HTTP接口，调用方必须先完成平台授权、签名验证、店铺归属及会话关联检查。

真实发送确认入口已经记录接待版本和使用的回复方式。授权数据接入后可以沿用本版流程，不需重新建设学习数据库和回复策略入口。但本版尚未取得或验证任何真实抖店接口权限。

## 已验证和仍需验证

已用构造店铺验证：5项已知缺陷修复、商家策略变更及回退、纠错候选生成与模型回归、模拟和真实接待隔离、订单去重、退款和乱序、完整覆盖、观察门槛、受控方式选择、版本隔离和库存变化持续积累。

真实千问复测58轮通过58轮；另验证“不会回答 → 商家纠正 → 候选 → 千问回归 → 确认启用 → 同义问法正确答复”。测试没有向飞鸽顾客发送消息。

仍需真实店铺验证：订单与会话关联的完整性、长时间运行、真实售后漏转与重复追问、商家纠错工作量、不同流量条件下的成交变化。构造测试的通过率不能作为销售时的真实准确率或成交提升宣传。
