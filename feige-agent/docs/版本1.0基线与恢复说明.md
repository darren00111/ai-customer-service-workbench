# 飞鸽客服 1.0 稳定基线

## 版本标识

- 产品版本：`1.0.0`
- Git 标签：`v1.0.0`
- 版本文件：项目根目录 `VERSION`
- 程序内版本：`app/__init__.py` 中的 `__version__`
- 发布归档：`releases/v1.0.0/FeigeCustomerService-1.0.0.zip`
- 归档校验：同目录 `SHA256SUMS.txt`

Git 标签对应的提交是源代码基线；ZIP 是不依赖当前工作区的离线恢复副本。两者共同用于回滚。

## 基线包含内容

1. `feige-agent` 的桌面控制台、十店监督器、页面代理、回复流水线、会话状态、通知队列和测试。
2. `feige-fashion-customer-service` 的分类规则、商品知识库、模板、参考资料和测试脚本。
3. Windows 桌面程序完整目录 `dist/FeigeCustomerService`，包括 EXE、运行库、十店配置模板、知识库和使用说明。
4. 构建脚本、依赖清单和项目文档。

## 不包含内容

以下内容属于持续变化或敏感的运行数据，不进入 Git 和发布归档：

- 浏览器登录缓存、Cookie 和各店铺 profile；
- 客户对话状态、客服日志和人工通知队列；
- Python 虚拟环境、构建缓存和临时诊断文件。

恢复程序后需要重新登录店铺。正式店铺知识库若在 1.0 之后单独更新，应另行备份，不应依赖代码回滚覆盖。

## 1.0 功能范围

- 至少十个店铺的独立浏览器、端口、登录目录和运行状态；
- 店铺手动启动、停止和并发监督，关闭浏览器后不强制重启；
- 售前规则回复、缺少商品或尺码资料时的自动补问；
- 售后、质量、投诉、议价和低置信度问题的人工草稿；
- 草稿编辑、发送前会话复核、人工接管锁和处理完成恢复；
- 稳定消息指纹、发送前占用和重复回复保护；
- 本地桌面控制台和 Windows 可执行程序。

后续版本是在这个范围上继续增加功能或修改行为。`v1.0.0` 标签和归档保持不变，因此后续修改不会覆盖本基线。

## 恢复方式

### 只恢复可运行程序

1. 校验 ZIP 的 SHA-256 是否与 `SHA256SUMS.txt` 一致。
2. 把 ZIP 解压到新的目录。
3. 打开 `feige-agent/dist/FeigeCustomerService/FeigeCustomerService.exe`。
4. 重新登录需要使用的店铺。

这种方式不会改动当前开发工作区，最适合临时回到稳定版。

### 从 Git 建立独立的 1.0 恢复分支

在仓库根目录执行：

```powershell
git switch -c recovery-v1.0.0 v1.0.0
```

这会从 1.0 标签创建一个独立分支，保留当前分支和后续提交。若该分支名已经存在，可改用其他名称。

### 核对当前源码是否为 1.0

```powershell
git describe --tags --exact-match
Get-Content .\feige-agent\VERSION
```

两项应分别显示 `v1.0.0` 和 `1.0.0`。

## 运行数据恢复原则

代码回滚不自动回滚客户会话、登录状态或日志。需要保留运行数据时，应在切换版本前单独备份 `data` 下的 profile、stores、logs 和 notifications 文件，并在确认数据格式兼容后恢复。
