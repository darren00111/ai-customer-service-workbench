# 接入配置

## 通知通道优先级

| 通道 | 状态 | 适用阶段 |
|---|---|---|
| 个人微信桌面端 | ✅ **试运行已验证** | 有人值守的人工监督测试 |
| 企业微信群机器人 | ✅ **推荐的正式通道** | 任何阶段，含无人值守 |

> **实测结论（2026-09-22）：个人微信当前会话直发已成功。**
> 脚本经 `clip.exe` 管道写剪贴板时，智能体运行环境的 `PYTHONUTF8=1` 使 Python 按 UTF-8 编码输出，
> 而系统 ANSI 代码页是 GBK（936），微信按 GBK 解释后搜索框出现乱码（用户截图证实为「鑴囧欢…」式乱码），
> 搜索无法命中会话。现已改用 Win32 `CF_UNICODETEXT` 直接写入，绕过代码页转换。
> 在人工预先打开并确认“文件传输助手”的条件下，使用 `--current-chat` 跳过搜索框，真实通知已确认送达。

## 飞鸽网页

1. 使用商家已授权的浏览器账号登录飞鸽，并保持一个明确的店铺上下文。
2. 第一次接入时只处理测试账号或指定会话，标定未读列表、店铺名称、商品卡片、输入框、发送按钮、转人工入口和会话链接。
3. 用三类测试验证：普通尺码咨询、资料缺失咨询、退换货咨询。
4. 确认不会切错店铺、重复发送，并能在转人工后停止该会话的自动回复，再逐步扩大范围。

页面结构改变、登录失效、弹出验证码或关键控件无法识别时，停止自动发送并通知人工重新标定。

第一次联调时，先人工点击“立即上线”，再用测试买家发起一条普通尺码咨询。不要使用真实售后订单完成首次发送测试。

## 个人微信通知（有人值守试运行）

默认测试目标为「文件传输助手」。除用户另行指定精确会话名称外，一律使用它。

**当前状态：可用于有人值守的试运行。** 操作员需预先打开并核对目标会话，再使用 `--current-chat` 发送。若用于无人值守或正式百店业务通知，请改用企微群机器人。

前置条件：

1. 电脑端微信保持登录、解锁，窗口可被唤起至前台。
2. 微信未被锁定、未弹出扫码或安全验证。
3. 桌面处于可交互状态（非锁屏、非仅远程无界面会话）。
4. **输入法切换为英文（EN）**——中文输入法会拦截 `Ctrl+F` / `Ctrl+V`。
5. 全程有人盯着，随时准备中断。

### 已知限制（微信 4.x）

| 项 | 事实 |
|---|---|
| 进程名 | `Weixin.exe`（旧版为 `WeChat.exe`） |
| 主窗口类名 | `Qt51514QWindowIcon`（旧版为 `WeChatMainWndForPC`） |
| 主窗口标题 | 非「微信」，实测为 `Rl`；**不可靠，禁止按标题匹配** |
| UI Automation | **不可用**。控件树仅 1 个空 Pane（`MMUIRenderSubWindowHW`），无 Edit/Document/Button |
| 窗口定位方式 | 必须按窗口类名 + 进程名 + 可见性枚举，见脚本 `find_wechat_hwnd()` |
| 模拟按键 | 中文输入法下 `Ctrl+F` / `Ctrl+V` 可能失效；且与其它前台窗口存在焦点竞争 |
| 搜索框选中 | 粘贴会话名后**必须先按 `↓` 再回车**，否则文字滞留在搜索框，回车无效 |
| 剪贴板编码 | **已修复**：`clip.exe` 管道 + `PYTHONUTF8=1` → UTF-8 字节被微信按 GBK 解释成乱码。现用 Win32 `CF_UNICODETEXT` 直写（`set_clipboard_unicode()`），与代码页无关 |

### 已证通的按键序列

```
激活窗口（并校验前台）
  → Ctrl+F          打开搜索框
  → Ctrl+A, Delete  清空残留文本
  → 粘贴会话名
  → ↓               选中第一条搜索结果［关键步骤，缺了必失败］
  → 回车            打开该会话
  → 粘贴消息正文
  → 回车            发送
```

搜索序列仍需继续验证。当前已证实可靠的试运行路径是：人工打开目标会话，再使用 `--current-chat` 直接粘贴发送。

投递流程：

1. 先只准备消息，不触碰桌面：

```powershell
python scripts/notify_wecom.py --store "店铺A" --customer "会话尾号1234" --category "退换货" --summary "顾客申请换大一码，订单状态待核实"
```

2. 核对输出中的店铺、脱敏会话尾号、分类、摘要，以及目标会话标题是否完全一致。
3. 向用户取得针对这条消息和这个目标的即时确认。
4. 确认后执行真实投递：

```powershell
python scripts/notify_wecom.py --store "店铺A" --customer "会话尾号1234" --category "退换货" --summary "顾客申请换大一码，订单状态待核实" --send --confirm-send
```

5. 投递后检查消息确实出现在目标会话中。未确认出现即视为失败，保留飞鸽转人工状态并在本地报告。

当操作员已打开并确认目标会话时，使用：

```powershell
python scripts/notify_wecom.py --store "店铺A" --customer "会话尾号1234" --category "退换货" --summary "顾客申请换大一码，订单状态待核实" --current-chat --send --confirm-send
```

`--current-chat` 会跳过微信搜索。它只适用于人工已经确认当前会话名称的场景；脚本无法自行验证聊天标题。

指定其他会话时追加 `--chat "群名或好友名"`。标题按字面比对，模糊匹配不算命中。

投递前脚本会自动脱敏：手机号保留前三后四，身份证号整段隐藏，8 位以上连续数字只保留末四位。会话标题只做手机号与身份证脱敏，避免误伤「旗舰店12号」这类正常店名。

真实发送需要 `--send` 与 `--confirm-send` 同时出现；只给 `--send` 会被拒绝（退出码 5），不会误发。

个人微信桌面自动化要求电脑保持登录、解锁和界面可操作，适合有人值守的试运行。搜索框自动定位序列尚未完全收敛；正式或无人值守场景请用下面的企业微信群机器人。

## 企业微信群机器人（推荐通道）

在目标企业微信群添加群机器人，复制 webhook，并把它存入运行环境变量 `WECOM_WEBHOOK_URL`。不要把 webhook 写进 Skill、代码仓库或商品资料。

PowerShell 当前会话示例：

```powershell
$env:WECOM_WEBHOOK_URL = "机器人 webhook"
```

先执行 `--channel webhook --dry-run` 检查 payload 与脱敏结果，再在测试群发送一条真实通知：

```powershell
python scripts/notify_wecom.py --store "店铺A" --customer "会话尾号1234" --category "退换货" --summary "顾客申请换大一码，订单状态待核实" --channel webhook --dry-run
```

切换通道时只改投递适配器，`SKILL.md` 中的转人工规则与隐私规则保持不变。
